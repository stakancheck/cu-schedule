# Свободные аудитории ЦУ

Интерактивный план кампуса со статусами аудиторий и расписанием на день.

## Запуск

React + TypeScript, сборка Vite. Нужен Node 20+.

```bash
npm install
npm run dev        # http://localhost:8765, изменения видны сразу
npm run build      # проверка типов и сборка в dist/
```

Онлайн-версия: https://stakancheck.github.io/cu-schedule/

Публикация: `.github/workflows/pages.yml` собирает сайт на каждый пуш в `main` и выкладывает на
GitHub Pages. В настройках репозитория (Settings -> Pages -> Source) должно стоять «GitHub Actions»:
из самой ветки Pages собранный сайт не отдаст.

## Обновление расписания

Автоматически: GitHub Actions (`.github/workflows/update-schedule.yml`) каждую ночь в 02:30 МСК
скачивает выгрузку с [cu-schedule.ru](https://cu-schedule.ru/) (та же, что «Скачать Excel -> Списком ->
Всё расписание»), и если файл изменился, пересобирает базу, коммитит и публикует сайт заново.
Запустить вручную: вкладка Actions -> «Обновление расписания» -> Run workflow.

Вручную локально:

```bash
python3 scripts/update.py
```

Или из своего xlsx:

```bash
python3 scripts/build_db.py raspisanie-spiskom.xlsx
```

## Обновить планы кампусов

Планы обоих кампусов парсятся из официальных PDF (векторы стен, иконок и улиц, контуры
аудиторий через сегментацию):

```bash
python3 scripts/parse_plan.py ct ~/Downloads/ЦТ_план.pdf
python3 scripts/parse_plan.py ducat ~/Downloads/plan-ducat.pdf
```

Нужны `pymupdf`, `opencv-python`, `numpy`.

## Структура

- `scripts/update.py` - скачивает свежий xlsx и пересобирает базу, если он изменился.
- `scripts/build_db.py` - парсер xlsx (листы по неделям).
- `data/schedule.csv` - полная база: одна строка на занятие, аудитории через `;`, дубли из исходника убраны.
- `data/rooms.csv` - справочник аудиторий (кампус, этаж, число занятий).
- `public/data/schedule.js` - компактная база для приложения.
- `scripts/parse_plan.py` - парсер PDF-планов кампусов.
- `public/data/plans-ct.js`, `public/data/plans-ducat.js` - сгенерированная геометрия этажей ЦТ и Дуката, руками не править.

Данные из `public/data` грузятся обычными скриптами до приложения (`window.SCHEDULE`, `window.CAMPUSES`):
ночное обновление расписания не меняет код, а бандл остаётся маленьким.

Приложение (`src/`):

- `lib/schedule.ts` - пары по датам, занятость и статусы аудиторий.
- `lib/store.ts` - состояние приложения и его синхронизация с адресом, `lib/actions.ts` - все действия.
- `lib/account.ts`, `lib/mine.ts`, `worker/` - личное расписание из Яндекс Календаря (см. ниже).
- `lib/telegram.ts` - всё, что связано с Telegram Mini App.
- `plan/PlanRenderer.ts` - план этажа: SVG из векторов, поворот, масштаб, жесты, слой маршрута.
  Это не React-компонент: тысячи путей и анимация камеры идут напрямую в DOM.
- `nav/engine.ts` - поиск маршрутов, `nav/data.ts` - ручная разметка лестниц, лифтов, входов и туалетов,
  `nav/places.ts` и `nav/steps.ts` - места для поиска и шаги маршрута.
- `nav/info.ts` - что за место на плане: категория, описание, подробности (правится руками, см. ниже).
- `components/Search.tsx` - общий поиск, `components/Place.tsx` - карточка места.
- `components/` - интерфейс, `styles/app.css` - стили и темы.

## Маршруты

Кнопка «Маршрут» на плане, «Отсюда / Сюда» в карточке аудитории, «Как пройти» у своей пары.
Откуда и куда: аудитория, помещение или подпись с плана, вход, «ближайший туалет» или
«ближайшая кухня или кафе». Предлагается до трёх вариантов (рекомендуемый, без лестниц, без лифта)
и пошаговый режим: «пройдите до лестницы», «поднимитесь на 3 этаж», «пройдите до аудитории».

Как устроено (`src/nav/engine.ts`):

- каждый этаж растеризуется в сетку прямо из векторов плана: пол проходим, стены и атриум нет,
  проёмы в стенах и есть двери. Через чужие помещения идти дорого, у стен чуть дороже, чем
  посередине коридора;
- между этажами ходим только по связям из разметки. Верхний уровень - маленький граф из старта,
  финиша и остановок лестниц и лифтов, расстояния по этажам считает Дейкстра по сетке;
- время: шаг 1.2 м/с, лестница 16 с на этаж вверх и 11 вниз, лифт 40 с ожидания + 6 с на этаж.

Разметка лежит в `src/nav/data.ts` и правится руками: лестницы и лифты (точка на каждом этаже,
`oneway`, `closed`), входы, туалеты, масштаб в метрах, `holes` - дыры в полу, которых нет в PDF
(так на 2 этаже Дуката поправлены переходы между корпусами B и F). Для правки откройте сайт с `?navdebug`
в адресе (`http://localhost:8765/?navdebug`): на плане видна сетка проходимости (красное -
непроходимо, оранжевое - замкнутые карманы), подписаны остановки, а клик по плану печатает
координаты в консоль.

## Поиск

Кнопка с лупой на плане (на компьютере ещё Ctrl/⌘ K и «/»). Ищет сразу по всему:

- аудитории, в том числе в русской раскладке («т318» = N318), со статусом на время плана;
- места на плане: помещения, подписи, туалеты, лестницы и лифты, а также по их описаниям
  и подробностям из `nav/info.ts` (записали «кофемашина» - найдётся по «кофемашина»);
- преподаватели, предметы и потоки из расписания. Они открываются списком пар на три недели вперёд,
  нажатие на пару или аудиторию ставит план на её день и время.

Без запроса - быстрые действия (ближайший туалет и где поесть с маршрутом от выбранного места,
свободные аудитории, коворкинг, гардероб, маршрут) и недавнее.

## Места на плане

Нажимается не только аудитория с расписанием, а всё, что подписано на плане: помещения Дуката,
подписи ЦТ («Кухня», «Техно точка», «Учебный офис»), иконки туалетов, лестниц, лифтов, кухонь,
гардероба и ресепшна. Открывается карточка: что это, подробности, похожие места рядом, маршрут
«Отсюда / Сюда». Выбранное место хранится в адресе (`pl=...`), ссылкой можно поделиться.

Описания в `src/nav/info.ts`:

- `RULES` - общее описание по названию («Переговорная», «Кухня», «Офис преподавателей»):
  только то, что следует из названия;
- `NOTES` - подробности конкретного места: `facts` (нюансы списком: есть кофемашина, нет розеток),
  `hours`, `who`, `about` (заменяет общее описание). Ключ - код помещения (`"B311"`) или
  кампус, этаж и подпись (`"CT 3 Техно точка"`). Пока подробностей нет, карточка предлагает
  написать и дополнить.

## Мои пары (Яндекс Календарь)

Студент входит своим аккаунтом ЦУ и видит только свои пары: план сам ничего не подсвечивает,
по нажатию на аудиторию в списке она открывается на плане, есть ссылка на звонок, маршрут,
отметки «приду / возможно / не приду» для одного занятия или всей серии. Данные берутся из
личного Яндекс Календаря по CalDAV, преподаватели подтягиваются из общей базы.

Как устроено:

- `worker/` - API на Cloudflare Workers без базы данных. Ходит в `caldav.yandex.ru`,
  разворачивает серии (RRULE, EXDATE, замены по RECURRENCE-ID), разбирает название
  «Предмет, Тип, B214 + B216 (Дукат)», меняет статус участника с `If-Match`, чтобы не затереть
  правку диспетчера. Логин и пароль приложения лежат только внутри зашифрованной (AES-GCM)
  сессии, которую хранит браузер студента.
- `src/lib/account.ts` - сессия, кэш событий в `localStorage`, фоновая синхронизация
  (раз в 5 минут и при возврате на вкладку; если календарь не менялся, ответ пустой).
- адрес API задан в начале `src/lib/account.ts` (прод: `https://cu-schedule-api.cu-schedule-api.workers.dev`). Если он пустой, вход на сайте не показывается.

Вход сейчас по паролю приложения (Яндекс ID → Безопасность → Пароли приложений → Календарь).
Вход через Яндекс ID (SSO университета) добавляется новым провайдером в
`worker/src/providers.js`: план там же, клиенту достаточно получить ту же сессию.

Локально:

```bash
cd worker && npm run dev          # API на :8787, ключ сессий сам создаётся в .dev.vars
npm run dev                       # сайт, на localhost сам ходит в локальный API
cd worker && npm test             # тесты разбора, развёртки, отметок и API
```

Деплой API (один раз):

```bash
cd worker
npx wrangler@4 login
openssl rand -base64 32 | npx wrangler@4 secret put SESSION_KEY
npx wrangler@4 deploy
```

Адрес Worker прописан в `src/lib/account.ts`; при смене аккаунта или имени поправить там.
Смена `SESSION_KEY` завершает все сессии.

Проверить доступ к календарю и формат событий без сайта: `python3 scripts/caldav_probe.py`.

## Telegram Mini App

Сайт работает как мини-апп: учитывает системные отступы и кнопки Telegram в полноэкранном режиме,
берёт высоту из `--tg-viewport-stable-height`, отключает сворачивание свайпом (чтобы двигать план),
в режиме «как в системе» повторяет тему Telegram и красит под неё шапку. Системная кнопка «Назад»
сбрасывает выбранную аудиторию. Вне Telegram всё это не включается.

## Управление

- Клик по аудитории: на компьютере её расписание в правой колонке, на телефоне карточка поверх плана
  (идущая или следующая пара, маршрут), из неё «Расписание» открывает экран аудитории. Общая вкладка
  «Расписание» от выбора на плане не зависит. Esc сбрасывает выбор.
- Стрелки влево/вправо: день назад/вперёд. Цифры: этаж (0 = 10 этаж). R: повернуть план.
- Колесо или щипок: масштаб, перетаскивание: сдвиг плана.
- Состояние (этаж, дата, время, аудитория, поворот, маршрут) хранится в адресе, ссылкой можно поделиться.
